# 通用编码规范（语言无关）

> 适用：编码实现阶段。语言特有写法见 `languages/` 对应文件的同名章节。

## 1. 命名
语义化、一致、可读；避免缩写歧义与魔法数字；遵循项目已有约定，无约定用语言主流规范。

## 2. 结构
函数短小、职责单一；控制嵌套层级；尽早返回。

## 3. 错误处理
- 区分可恢复与不可恢复错误；提供上下文信息。
- 失败显式化：错误要被看见、被记录、被处理；**禁止静默吞异常或用宽泛 catch 掩盖真实错误**。
- 边界做错误转换（底层错误→领域错误），核心逻辑不吞错。

## 4. 并发与资源
（思想层）注意竞态、死锁、资源泄漏；及时释放句柄；取消与超时要有明确语义。具体模型见语言文件第 7 章。

## 5. 依赖
显式声明版本，避免不必要依赖；评估许可证风险；锁文件要提交。

## 6. 注释（分层 · 硬要求）
**结构声明层——必须有良好注释**：
- 文件级：用途与职责
- 类/接口/类型级：承担什么角色
- **公开 API**：用途、参数、返回值、异常/边界、调用约定（硬要求）
- 函数/方法签名：做什么、何时调用
- 公开字段与常量：含义、单位、取值约束
- 非显然的公开变量：为什么存在
- 注释写清"是什么 + 怎么用 + 约束"，用项目约定的文档格式（JSDoc / docstring / Go doc / JavaDoc / rustdoc）

**函数体内逻辑代码——保持克制**：
- 只在"为什么"非写不可时落笔：意图、权衡、坑、非常规做法。
- 代码本身能看出的"这行做什么"不写。

两者不矛盾：声明层靠注释交代契约，实现层靠代码自解释、注释只补代码说不出的原因。遵循工程记忆里记录的注释风格，无约定用语言主流规范。

## 7. 格式
遵循格式化工具与 lint 规则，提交前统一格式化。
