# 门拦截度量（规范自我反馈）

> 适用：想知道"这套规范好不好用、哪条门总在拦人、哪条纪律总被绕过"时。来源：2026-11-23 补规范自身反馈环。
>
> **铁律（防耦合）**：本文件只定义**记什么字段、记在哪、何时回看**——**不存放任何项目数据、流水或统计结果**。度量数据留在 `.project_memory/tmp/`，长期教训才写回工程记忆规范层或 skill 的 CHANGELOG。skill 是全局规则，项目事实不进 skill（同 `core/project-memory.md` 只存规范不存流水）。

## 1. 记什么（最小字段）

每次任务在 `.project_memory/tmp/` 的 `GATE-LOG.md`（与 PROGRESS.md 同类的临时产物，不进规范层）追加一行：

| 字段 | 取值 | 说明 |
|---|---|---|
| 日期 | YYYY-MM-DD | 任务日期 |
| 阶段 | 产品/架构/研发/测试/评审/运维 | §2.1 五环节 + 评审 |
| 门 | G1/G2/G3 或其它检查 | 触发的是哪道门 |
| 结果 | 拦住 / 通过 / 绕过 | 拦住=按门停下要缺失物；通过=满足条件放行；绕过=未满足却推进了 |
| 缺什么 | 一句话 | 拦住或绕过时，上游交接物缺什么 |
| 处置 | 一句话 | 补齐了什么 / 谁拍板 / 为何绕过 |

只记这 6 个字段，不记对话全文。追加不覆盖（同 Ledger 纪律）。

## 2. 记在哪（落点分离）

- **`.project_memory/tmp/GATE-LOG.md`**：原始行，临时产物，任务结束可清理，不进规范层。
- **工程记忆规范层**：只有"某道门反复拦在同一处"这类**长期教训**才写回（标日期、带证据），原始流水不写。
- **skill CHANGELOG**：只有"规范本身需要改"的结论才写回（改动记录），不写项目统计。

## 3. 何时回看

- 每完成 ~5 个任务或会话末复盘时（见 `core/retrospective.md`），扫一遍 GATE-LOG：
  - 某门反复"拦住"同一类缺失 → 上游环节或该门的进入条件定义有问题 → 写回工程记忆规范层或提规范修订。
  - 出现"绕过" → 查是纪律太重被绕，还是门没写清 → 调整规范，不责备执行者。
  - 门长期零触发 → 可能是形同虚设，核对它是否真的在起作用。
- 回看结论写成一句话判断 + 证据指针（GATE-LOG 行号或文件:行），不写成长篇报告。

## 4. 完成检查

- [ ] 度量数据只在 `.project_memory/tmp/GATE-LOG.md`，未写进 skill 或工程记忆的规范层？
- [ ] 只记 6 个最小字段，追加不覆盖？
- [ ] 回看结论是"规范要不要改"的判断 + 证据指针，长期教训才写回规范层？
