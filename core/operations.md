# 长任务与上下文管理

> 适用：长任务、上下文过半、离开后回来接力。来源：原 8.7。

## 1. PROGRESS.md（五节）
放 `.project_memory/tmp/`（临时产物，不进规范层——见 `core/memory/document-tree.md` §7）：
- **Goal**：含总验收
- **Done**：每步带命令 + 结果
- **Next**：首项 = 精确下一步
- **Open questions**
- **Key facts**：路径/命令/版本/踩过的坑/失败过的方案及原因
每验证一步才更新，<150 行，不放密钥。

## 2. Ledger（逐笔追踪）
表头：`时间 阶段 决定 原因 证据 结果`。首行写目标与完成条件；每步前重读目标行 + 末 10 行查漂移；**证据必须是指针**（hash / 文件:行 / 命令+结果 / 产物路径）；失败与回退也记，旧行不改只追加；连续 3 行无进展就停下报告。

## 3. 重置信号
重复旧答案 / 忘了 Key facts / 又在试失败过的方案 / 上下文过半 → 先收尾到已知状态，把 PROGRESS.md 重写成"仅凭此文件 + 仓库即可续"的交接；新会话只读它 + `git log -5`，先验证上个 Done 再动 Next。

## 4. 回来接力
用户问"到哪了"：只读、用新命令核状态，<100 字说清变化与意义，列出只有他能定的决定（改什么 / 证据 / 风险 / 建议 / 未知）。

## 5. 状态写文件
状态写文件不写聊天——换上下文仍可续、可审计。（只读会话无法落盘时退化为回复内结构化文本。）
