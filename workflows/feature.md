# 编排：新功能（需求到交付）

1. **需求澄清**：三句复述 + 四问 + 验收标准（见 `core/requirements.md`）。写不出"什么算做完了"→ 只问一个问题，不猜。
2. **G1 门（需求门 · 硬）**：核对 PRD 存在、验收标准可判定、且**人已确认**；不满足 → **停在此处，向人要需求，禁止进入第 3–5 步，尤其禁止写任何实现代码**（P0 第 9 条）。
3. **现状勘察**：读工程记忆 + 读要改的代码及其调用方 + **读对应语言规范**（`languages/`）。
4. **方案设计**：模块划分/数据流/接口契约/异常路径；非平凡设计写双草图（见 `core/design-principles.md`）；复杂方案先给用户确认。
5. **G2 门（设计门 · 硬）**：核对 ADR + 接口契约已落盘、人已确认技术选型；不满足 → **停在方案，找用户确认，禁止开工写代码**。
6. **计划分解**：编号 3–10 步，每步一动作 + 可判定验收，写入工作区的 PLAN.md（执行计划是临时产物，不进工程记忆；工程记忆只存长期规范，见 `core/project-memory.md`）。
7. **编码实现**：遵循语言规范与工程记忆约定；注释按分层规则（见 `core/coding-standards.md`）；小步提交、每步可编译。
8. **G3 门（编译/送审门 · 硬）**：核对代码可编译、窄检通过；不满足 → 先修到通过再往下，**没通过检查的改动不送审**。
9. **测试**：新增逻辑的单元/集成测试，覆盖正常/边界/异常（见 `core/testing-strategy.md`）。
10. **验证**：窄检→全套→贴输出；证据分级（见 `core/verification.md`）。
11. **联调（按需）**：多模块/服务拼起来验证时走 `core/integration.md`（契约对齐、端到端通路）；单模块跳过。
12. **用户验收（按需）**：交付前对照 PRD 验收标准逐条核，走 `core/acceptance.md`；用户不在场标"自验待确认"。
13. **评审自审**：范围/diff/findings，4 轮封顶（见 `core/review.md`）。
14. **交付**：交付说明 + PR（见 `core/delivery.md`）；规范有变写回工程记忆。
15. **发布（按需）**：涉及上线部署时，先走 `core/release-and-operate.md`（发布三件套 + 人做 go/no-go + 上线观察）；不涉及则跳过。
16. **追问**：完整流程走完后，问下一需求 + 是否需要调整修正，然后停下（见 SKILL.md 第六节）。
