# 编排：问题排查（根因不明）

1. **界定问题**：现象是什么、何时开始、影响范围、复现条件；区分"观察到的事实"与"猜测"。
2. **建假设清单**：列出所有可能原因，不急于锁定第一个。
3. **最便宜探针优先**：用 print、日志、`which`/`--version`、`grep` 真实调用点、最小脚本、读已装版本文档——每个探针只测一个假设、给 yes/no（见 `core/verification.md` unstick）。
4. **逐条排除**：贴出每个探针结果，划掉被证伪的假设；不凭"应该不是"排除。
5. **锁定根因**：剩下的假设用更直接的方式确认（读代码/复现路径/运行中观测）。
6. **修复与验证**：转 `workflows/bugfix.md` 的修复步骤，或按 `core/verification.md` 处理。
7. **记录**：根因、排除过程、关键事实写入 PROGRESS.md 的 Key facts（见 `core/operations.md`），避免下次重复排查。
