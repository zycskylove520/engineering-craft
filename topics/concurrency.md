# 并发与并行（横切专题）

## 1. 先问要不要并发
能用顺序解决就别并发；并发引入的复杂度要换来明确收益。

## 2. 核心风险
- 竞态：共享状态被并发修改；用锁/不可变/消息传递规避。
- 死锁：锁顺序不一致；避免嵌套锁、设置超时。
- 活锁与饥饿：退避与公平性。
- 内存可见性/内存模型：按语言的具体模型处理（见语言文件第 7 章）。

## 3. 设计原则
- 优先不可变数据、消息传递；共享可变状态最小化且边界清晰。
- 明确取消与超时语义；后台任务可终止、有生命周期管理。
- 线程池/协程池限流，不无限创建。

## 4. 测试
并发 bug 难复现：用压力测试、竞态检测工具（如 TSAN、race detector）、确定性调度测试；不靠"跑几次没事"。

## 5. 验证
并发改动要专门验证（负载测试 + 竞态检测），不能只跑单测就宣称线程安全。
