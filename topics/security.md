# 安全工程（横切专题）

## 1. 输入即不可信
- 所有外部输入（用户、网络、文件、环境变量、第三方响应）在边界校验，白名单优于黑名单。
- 长度/类型/范围/格式全部限制；失败显式拒绝，不静默修正。

## 2. 常见注入
- SQL 用参数化查询/ ORM，不拼字符串。
- 命令执行避免 shell 拼接；路径操作防目录穿越（规范化 + 白名单根）。
- **路径 containment 按"实际落盘语义"校验，不按文本标签语义**（硬要求）：校验"目标是否落在根内"时，必须按宿主文件系统真正的解析语义折叠分隔符、`..`、盘符/UNC 再判断，不能只做字符串前缀比较——同一个标签在不同宿主上的解析可能不同（实测教训：POSIX 风格标签在 Windows 宿主上校验放行 `..\evil.md`，但落盘解析到根外）。返回值可按标签形态保留，但**安全判定一律以落盘语义为准**；根是文件系统根时前缀要去掉尾部分隔符，否则双分隔符会误拒一切子路径。
- 路径归一化要折叠 `./`、`../`、尾部斜杠并统一大小写后再比较归属，防 `src/a.js` 与 `src/./a.js`、`src/a.js/` 被当成不同文件而绕过重叠检测（并行写同一文件互相覆盖）。
- XSS/模板注入按上下文转义；反序列化只用可信源。

## 3. 密钥与敏感信息
- 密钥不硬编码、不入日志、不进仓库；用环境变量/密钥管理服务。
- 日志脱敏（密码/令牌/个人信息）；错误信息不泄露内部细节。

## 4. 权限与最小授权
- 默认最小权限；每个操作问"是否有必要"；越权要显式拒绝。
- 认证与授权分离；会话/令牌有过期与撤销。

## 5. 依赖安全
- 依赖版本锁定；关注已知漏洞（audit/SCA）；评估许可证；减少不必要的依赖面。

扫一遍 diff 里的密钥、隐私、注入点；把安全相关的假设写成测试。
