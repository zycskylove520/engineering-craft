# 重构手法（横切专题）

## 1. 安全前提
- 先有测试覆盖再重构；没有测试先补测试。
- 一次只做一种变换，每步跑检查保持绿（见 `workflows/refactor.md`）。

## 2. 常见坏味道
重复代码、过长函数、过大类、过长参数列表、发散式变化、霰弹式修改、数据泥团、基本类型偏执、 switch 泛滥、平行继承体系、冗余类、未来性过度设计。

## 3. 常用手法（小步）
提炼函数/变量/类、内联、搬移、改名、以多态取代条件、以对象取代数据组、拆解复杂条件、移除中间人、聚合/拆分。
每一步保持行为不变，靠测试担保。

## 4. 边界
- 重构不改变外部行为；要改行为是功能变更，走 `workflows/feature.md`。
- 大重构拆成可独立验证的小步；每步可回退。

## 5. 收尾
形成的新的架构/命名约定写回工程记忆；注释随结构调整同步（公开 API 契约尤其）。
